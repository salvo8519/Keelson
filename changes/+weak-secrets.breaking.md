Staging and production refuse to start with a weak secret: each checked secret needs at least 32 characters, 8 of them different (16 for an access key id such as `S3_ACCESS_KEY`), must not be a stand-in or a value of `garage/development.env`, and must not be made mostly of well-known words (look-alike substitutions such as `P@ssw0rd` included), stand-in phrases, the project name, runs of neighbouring characters, one repeated piece or doubled characters; `cmd garage-bootstrap` applies the same rule to `GARAGE_ADMIN_TOKEN` and `GARAGE_RPC_SECRET`, and the optional list now covers `QDRANT_API_KEY`, `SLACK_SIGNING_SECRET`, `RESEND_API_KEY` and the Stripe keys. To upgrade, regenerate every refused value before deploying, including existing secrets of 16 to 31 characters, with `openssl rand -hex 32`. `POSTGRES_PASSWORD` and `POSTGRES_APP_PASSWORD` are also stored in PostgreSQL, so set them there first, with the current values still in `backend/.env`: `docker compose --env-file backend/.env -f docker-compose.prod.yml run --rm -e ENVIRONMENT=development app <project> cmd rotate-database-passwords` (new command, prompts for both values and sends PostgreSQL only their SCRAM-SHA-256 verifiers), or `\password` for both roles in `psql` as the owner login; then write the new values to `backend/.env` and restart, with a short outage in between. Database passwords must now be printable ASCII without surrounding spaces, and `POSTGRES_APP_USER` must differ from `POSTGRES_USER`. Steps in the configuration guide, "Changing the database passwords". A workload credential now stops when its trust's issuer, audience or claims change or its lifetime is shortened; credentials issued before the update lack the trust digest and are refused, so running CI jobs must exchange their token again.
